# GCAI design-sync notes

- **No dist/library entry.** GCAI is a private Vite app (`package.json` has no `main`/`module`/`exports`), not a publishable component package. The converter runs in synth-entry mode, scanning `src/app/components/ui` (`cfg.srcDir`) directly for PascalCase component exports. There is no `cfg.buildCmd` step to build a library — `buildCmd` instead documents the site build + CSS-snapshot step needed for `cssEntry` (see below).
- **Scope: `src/app/components/ui` only.** This is the actual shadcn/Radix design system (48 files). Excluded from sync: `src/app/components/grid-concepts-homepage.tsx` and `ai-state-report.tsx` (page-level compositions, not reusable DS components) and `src/imports/` (raw Figma/Make export dumps).
- **9 shadcn components had missing peer deps** (chart, carousel, command, drawer, input-otp, calendar, sonner, form, resizable) — none were imported anywhere else in the app, so `npm run build` never caught it. Installed: `recharts`, `embla-carousel-react`, `cmdk`, `vaul`, `input-otp`, `react-day-picker`, `sonner`, `next-themes`, `react-hook-form`, `react-resizable-panels`. Without these installed, those 9 components fail to bundle (`[UNRESOLVED_IMPORT]`).
- **`node_modules/gcai` must be a junction back to the repo root** (`New-Item -ItemType Junction`), because the converter's package-shape PKG_DIR resolution is `join(NODE_MODULES, cfg.pkg)` when no `--entry` is passed — and `--entry` must NOT be passed here (see below). A stray, non-live `node_modules/gcai` directory existed before this sync (unrelated npm/pnpm artifact, confirmed stale via a marker-file test) and was deleted and replaced with a real junction. **`npm install` prunes the junction as an "extraneous" entry every time it runs** (confirmed: it vanished after installing `react-hook-form`/`react-resizable-panels`) — recreate it after ANY `npm install` in this repo, right before running the converter: PowerShell `Remove-Item node_modules\gcai -Force -Recurse -ErrorAction SilentlyContinue; New-Item -ItemType Junction -Path node_modules\gcai -Target (Get-Location)`.
- **Never pass `--entry` for this repo.** `--entry` is trusted blindly as an already-built dist file (see `resolveDistEntry` in `lib/bundle.mjs`) — passing anything (even just to help locate PKG_DIR) suppresses the no-dist synth-from-`src/` fallback entirely and produces a bogus near-empty bundle. Rely on the `node_modules/gcai` junction instead.
- **`cssEntry` is a generated snapshot, not a source file.** Tailwind v4 (`@tailwindcss/vite`) only produces real compiled utility CSS via the Vite build — the source `src/styles/*.css` files are just `@import`/`@source` directives, not usable CSS on their own. `cfg.buildCmd` (`npm run build:site && cp dist/assets/index-*.css .design-sync/.cache/compiled-tailwind.css`) rebuilds the site and snapshots the hashed output CSS to a fixed cache path (`cfg.cssEntry`) since the real dist filename is content-hashed and changes per build. Re-run this whenever `src/app/components/ui` or its Tailwind usage changes, before re-running the converter.
- **Two theme files both define `:root` tokens** — `src/styles/theme.css` (brand green, `--primary:#92ad39`) and `default_shadcn_theme.css` (imported later, inside `globals.css`; generic shadcn default, `--primary:#030213`). Cascade order means the generic default wins in the actually-shipped CSS (confirmed in the compiled dist output) — that's simply what ships today, not something this sync changed or should silently "fix". Flagged here in case it's not intentional on the site side.
- **Fonts**: Inter/Lora load via a Google Fonts CDN `@import url(...)` in `src/styles/fonts.css`, not shipped locally — set `runtimeFontPrefixes: ["Inter", "Lora"]` so validate doesn't flag `[FONT_MISSING]`.
- **Guidelines**: top-level `guidelines/Guidelines.md` doesn't match the converter's default `guidelinesGlob` — set explicitly to `guidelines/**/*.md`.

## Preview authoring gotchas (from the batch fan-out)

- `RadioGroupItem`/`Switch` don't carry Radix's `peer` class, so `Label`'s `peer-disabled:opacity-50` never dims the label text next to a disabled control (only the control itself dims) — accurate to source, not a preview bug.
- Accordion's root `type` prop must match its `defaultValue` shape: `type="single" collapsible defaultValue="..."` (string) vs `type="multiple" defaultValue={[...]}` (array) — mixing them errors/misrenders.
- `Separator` is invisible without a sized/flex container: horizontal needs surrounding block content, vertical needs an explicit-height flex row or it collapses to zero height.
- `Skeleton` has no default size — every instance needs explicit inline `style` width/height (plus `borderRadius: 9999` for avatar-style circles).
- `BreadcrumbEllipsis` needs no children — it renders its own `MoreHorizontal` icon + hidden "More" label internally.
- **Real site bug found: shadcn `Button` isn't wrapped in `React.forwardRef`** (this repo is React 18, not 19, so a function component needs `forwardRef` for `asChild`/`Slot` ref-forwarding to work). Any `<XTrigger asChild><Button>...</Button></XTrigger>` composition where `X` is a Radix Popper-positioned primitive (Popover, Tooltip, DropdownMenu — anything that measures the trigger's `getBoundingClientRect()` to position floating content) silently fails to attach the measurement ref, and the floating content renders with a garbage position (observed: `top: -540px`, i.e. nowhere near the trigger) — NOT a capture-tool bug, reproducible with a bare Playwright screenshot of the built `.html` outside any design-sync tooling. **Fix used in the previews**: style the Trigger primitive directly via `buttonVariants(...)` (imported from `button.tsx`) instead of wrapping the broken `Button`, e.g. `<PopoverTrigger className={buttonVariants({variant:"outline"})}>Label</PopoverTrigger>`. This is a real, reproducible bug in the site's own component — worth fixing upstream (wrap `Button` in `React.forwardRef`) independent of this sync; using `Button` as an ordinary child (not as an `asChild` target) is unaffected and fine.
- Overlay/portal components split into two families:
  - **Dialog/Sheet/AlertDialog** (built on Radix Dialog, centers via `fixed; top/left:50%; translate(-50%,-50%)`): render correctly with **no inline style override at all** — just `defaultOpen` on the root. An earlier attempt to "neutralize" the fixed positioning via `style={{position:"static", transform:"none"}}` on the content element actually broke it (content painted at a nonsensical offset, e.g. `x:-284,y:-105`, even though `getComputedStyle` reported the override took effect — a real Chromium rendering discrepancy between computed style and the painted box for this specific transition, not a config or capture-tool issue). The DOM confirms why no override is needed: Radix portals this content directly onto `<body>` (not into the `.ds-single` wrapper), so the wrapper's `cardMode:single` viewport IS the effective centering context — a `{width, height}` viewport at least as large as the content is all that's required. `Dialog`/`AlertDialog`/`Sheet`/`Select` all still need `cfg.overrides.<Name>: {"cardMode": "single", ...}` to stop `[GRID_OVERFLOW]` (grid cells are too small/clip portaled content even when the content itself renders correctly) — but don't add a style override on top of it.
  - **Popover/Tooltip/DropdownMenu** (Radix Popper/floating-ui-based): the actual root cause (see the forwardRef bug above) was the broken trigger ref, not a capture-timing issue. Once the trigger uses `buttonVariants` styling instead of a broken `asChild`-wrapped `Button`, these render correctly in normal flow and don't strictly need `cardMode:single` for CORRECTNESS — it's kept anyway (`viewport` sized to the content) since Popper-positioned content can still be taller/wider than a standard grid cell.
  - All current `cfg.overrides` values (Card, Popover, Tooltip, DropdownMenu, Dialog, AlertDialog, Accordion, Tabs, Select, Sheet) are recorded in `config.json`.
- Badge's `default` variant (and other `bg-primary`-based components) render near-black rather than brand green — this is the theme-cascade issue above (`default_shadcn_theme.css` winning over `theme.css`), not a preview defect.

## Known render warns (standalone floor-card sub-parts — expected, not blocking)

These 34 components are sub-parts of a parent that IS authored (Card, Sheet, Table, Breadcrumb, Alert) or are floor-tier sub-parts of components deferred to floor-card tier — each renders fine when *composed inside its parent's authored preview*, but its own standalone floor card is a leaf/container with nothing to show alone (a lone `<td>`, an empty header/footer `<div>`, a label with no children context, etc.), so `package-validate.mjs` flags it `[RENDER_BLANK]`/`[RENDER_THIN]`. This is a deliberate scope trade-off (user chose "core ~20-25 authored, floor cards for the rest" over authoring all 238 individual exports) — authoring a standalone story for each would mean writing ~34 more trivial preview files for atomic pieces that only make sense in composition. Not treated as a re-sync regression unless the render check flags a NEW name not on this list:

AlertTitle, AspectRatio, BreadcrumbEllipsis, BreadcrumbItem, BreadcrumbSeparator, CardContent, CardFooter, CardHeader, ContextMenuLabel, DrawerFooter, DrawerHeader, DropdownMenuLabel, InputOTPSeparator, MenubarLabel, NavigationMenuItem, PaginationEllipsis, PaginationItem, PaginationLink, SheetFooter, SheetHeader, SidebarFooter, SidebarGroup, SidebarGroupLabel, SidebarHeader, SidebarInput, SidebarMenuItem, SidebarMenuSkeleton, SidebarMenuSub, SidebarMenuSubButton, SidebarMenuSubItem, SidebarProvider, TableCaption, TableCell, TableHead, Toggle.

## Re-sync risks
- The CSS snapshot (`.design-sync/.cache/compiled-tailwind.css`) goes stale the moment `src/app/components/ui/*.tsx` changes without re-running `cfg.buildCmd` — always rebuild before re-running the converter.
- The 7 newly-installed peer deps are real `dependencies` in `package.json`/lockfile now — if someone reverts that install, those 7 components will fail `[UNRESOLVED_IMPORT]` on the next sync.
- No per-component `.d.ts`/docs exist — every `.prompt.md` is synthesized from source + authored preview, so keep authored preview `.tsx` files reasonably documented (real prop values) since they double as the API reference.
